# 背景：替 AI 寫程式工具做原生核准彈窗，四次嘗試

[English](approval-popup-notes.md) | 繁體中文

AI 寫程式工具在執行指令或修改檔案前會停下來問。同時開好幾個的時候，不論是終端機分頁還是桌面 App 的對話，這些提示常常沒人看到。工作卡住了，卻沒有人知道。

我要的東西很單純：一個 macOS 原生視窗，蓋在我正在做的事情上面，顯示它在問什麼，並把我的回答送回發問的那個對話。

結果我做了四次，每個環境一次，decision-alert 是其中之一。這一頁說明為什麼一個版本不夠用，以及如果重來我會先做什麼。另外三個只講做法，不附程式碼。

## 先講結論

彈窗是簡單的部分，到哪裡都一樣。每個環境不同的是頭尾兩端：

1. **偵測**：怎麼知道有提示在等？
2. **回傳**：怎麼把答案送回正確的對話？

每個環境對這兩個問題的答案都不同，所以我手上是四套實作，不是一套。

## 四次嘗試

| 環境 | 涵蓋的 AI 工具 | 偵測 | 回傳 | 什麼會讓它失效 |
|---|---|---|---|---|
| 有腳本 API 的終端機（iTerm2） | Claude Code、Codex、Gemini CLI | 讀每個分頁的畫面，比對提示文字 | 對該分頁送出選項的按鍵 | 任何一個工具改了提示文案 |
| 讀不到畫面的終端機（Ghostty） | Claude Code | 工具自己的權限 hook | 以 JSON 把決定回傳給 hook | 仍是原型；涵蓋範圍取決於有哪些工具提供這種 hook |
| 可執行多家模型的桌面 App（T3 Code） | App 裡執行的各家模型 | 監看 App 的本機狀態，找出待處理的請求 | 透過 App 的本機介面回覆 | App 改了內部結構 |
| Claude 桌面版 | Claude | App 的 hook 機制，包成 mod | 把決定回傳給 hook | hook 的約定有變動 |

Claude 桌面版的版本就是這個 repo，請看 [README](../README.md)。另外三個在這裡只描述做法，這個外掛並不支援那些工具。

## 學到的事

### 讀畫面到處都能用，也最常壞

比對提示文字是唯一能涵蓋「沒有 hook 的工具」的方法，也是我修最多次的版本：一週內修了兩次，先是某個工具的權限提示選項數量不同，接著是各工具的問句文字不同。

如果走這條路，把比對規則集中在一處，並用真實的提示文字寫測試。要有持續更新的準備。

### 能接收決定的 hook，是最接近通用解的做法

當工具自己告訴你「這件事我需要許可」，並且接受以回傳值給它決定，兩個難題就同時消失。不用讀畫面，也不用送按鍵，用哪個終端機就不再重要。

限制在涵蓋範圍。這個做法我只在一個工具上做通。其他工具我只留了空殼，因為不想去猜一個我還沒確認過的介面。

### 讀 App 的內部狀態是最脆弱的一條路

它能用，而且涵蓋 App 裡執行的所有模型，但它依賴的是 App 從未承諾會保留的結構。要把它當成任何一次更新都可能失效的東西。

### 彈窗需要幾條安全規則

- **Enter 不可以等於核准。** 預設按鈕應該是「回到對話」，誤按一個鍵才不會放行指令。
- **自動確認預設關閉。** 我加了一個可選的「閒置 N 秒後自動確認」核取方塊。要使用者自己勾選，按鈕上會顯示倒數，任何滑鼠或鍵盤動作都會重置倒數。
- **顯示足以判斷的資訊。** 專案名稱、是哪個對話、指令或檔案，以及工具有提供的話，它的理由。
- **請求已在別處回答時，要關掉彈窗。** 否則你回答的是一個已經不存在的問題。
- **需要打字回答的問題不適合放在彈窗裡。** 發一則通知，把人帶回對話就好。

## 如果你要替另一個環境做這件事

動手前先回答這幾題：

1. 這個 AI 工具有沒有在權限請求時觸發、而且能接收決定的 hook？有的話就用它，不用往下看。
2. 沒有的話，工具之外的程式能不能讀到對話的畫面，又能不能對那一個特定的對話輸入？
3. 如果工具跑在桌面 App 裡，App 有沒有在你被允許讀取的地方公開待處理的請求？
4. 你要怎麼辨識是哪個對話在問，答案才不會送錯地方？

順序是有意義的。每往下一題，維護成本就比上一題高。
